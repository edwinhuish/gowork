# 实施路线

**这份文档只回答"先做什么、做到哪一步算完成"。**
每个能力做什么、为什么这个优先级，见 `docs/trade-erp-crm-blueprint.md`（下文用能力编号 `A1` / `B2` 引用它）；
业务对象命名见 `docs/glossary.md`。

---

## 一、排期原则

1. **沿业务主链推进，不按模块难度推进。** 先把"客户 → 报价 → 订单 → 出货 → 收款"接通，
   再回头补字段。链条断在哪，系统就会被 Excel 顶替。
2. **底座先行，且只做一次。** 币种、汇率、单据状态、单号这四件事被后面每张单据引用。
   先各模块自建一套，事后统一的成本是"改全部表 + 洗全部历史数据"。
3. **一个任务一次提交，且必须是可验证的完整切片。** 后端接口能往返、前端页面能操作、
   `task lint` 与 `task test` 通过，三者齐全才算完成。半截的中间态不提交。
4. **P2 不阻塞主链。** 遇到"顺手就能加"的 P2 能力，记在这里而不是当场做。
5. **对标补强不插队。** 阶段 7～9 是照主流外贸系统补的（单证、报表、数据范围），
   全是 P1/P2，排在主链之后。唯一例外是 T-24（PI）：若客户要求"先出 PI 再签单"，
   它可以提前到阶段 3 末尾，那时报价与订单的数据已经够用。

## 三、执行约定

每个任务收尾时必须同时完成这四件事，缺一件都算没做完：

1. 后端五层齐全（model → repository → dto → service → handler+router），并在
   `internal/bootstrap/app.go` 装配一次。
2. 前端页面能操作（列表 + 新建 / 编辑，需要详情的加详情），并在 `App.tsx` 的
   `resources` 与 `Routes` 各加一条。
3. 更新本文与蓝图里的状态列，新增术语写进 `docs/glossary.md`。
4. `gofmt -l .`、`go vet ./...`、`go test ./... -count=1`、`pnpm run typecheck`、
   `pnpm run build` 全部通过，然后提交一次。

**提交信息**沿用仓库既有风格：`type(scope): 中文概述`，正文说明取舍。

# 实施路线

**职责**：全项目**唯一的任务表**——编号、交付物、验收标准、依赖、优先级、进度，都只在这里维护。
**不管**：为什么需要这个能力（`docs/trade-erp-crm-blueprint.md`，下文用能力编号 `A1` / `B2` 引用它）、
差距证据与重构理由（`docs/gap-analysis.md`）、业务对象命名（`docs/glossary.md`）。
**相关**：`docs/gap-analysis.md` 第七章给出 T-37 起的任务「为什么建议做、建议插在哪」，本文只记结论与验收。

---

## 一、排期原则

1. **沿业务主链推进，不按模块难度推进。** 先把"客户 → 报价 → 订单 → 出货 → 收款"接通，
   再回头补字段。链条断在哪，系统就会被 Excel 顶替。
2. **底座先行，且只做一次。** 币种、汇率、单据状态、单号这四件事被后面每张单据引用。
   先各模块自建一套，事后统一的成本是"改全部表 + 洗全部历史数据"。
3. **一个任务一次提交，且必须是可验证的完整切片。** 后端接口能往返、前端页面能操作、
   `task lint` 与 `task test` 通过，三者齐全才算完成。半截的中间态不提交。
4. **P2 不阻塞主链。** 遇到"顺手就能加"的 P2 能力，记在这里而不是当场做。
5. **对标补强不插队。** 阶段 7～9 是照主流外贸系统补的（单证、报表、数据范围），
   全是 P1/P2，排在主链之后。唯一例外是 T-24（PI）：若客户要求"先出 PI 再签单"，
   它可以提前到阶段 3 末尾，那时报价与订单的数据已经够用。

**T-47 为什么排在阶段 3 收尾（P1）**：内部编号 `{主体编码}{YY}{NN}-{后缀}` 标的是「一笔生意」，
得等报价 → 订单 → 采购三段都在（T-10～T-13）才有东西可串；而一旦有了真实数据再改号，就要连带重编历史单。
它**不改对外单号格式**：`{类型2字母}-{YYYYMM}-{4位流水}` 本来就是代码现状，T-47 只补内部编号这一层，
以及两个类型码（`SH` → `DN`，新增 `CI` / `PL`）与采购表头的强制关联。细则见蓝图 §五.4。

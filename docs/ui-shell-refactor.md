# 应用外壳重构需求说明（Vben 视觉复刻 · React 实现）

**职责**：定义"外壳"（布局 / 主题 / 多标签页）要复刻到什么程度、行为边界在哪、哪些东西明确不做。
**不管**：业务页面的字段与口径（`apps/frontend/AGENTS.md`）、接口契约（`apps/backend/AGENTS.md`）、
取舍理由（`docs/architecture.md`）、任务进度（`docs/roadmap.md`）。
**相关**：`docs/glossary.md`（业务对象命名）、Vben Admin 5.7 演示站（视觉参考物）。

---

## 一、目标与前提

一句话：**借 Vben 的外观，不借它的内部结构。**

| 维度 | 结论 |
|---|---|
| 保留 | React 19 + TypeScript + Vite 6 + refine 5 + antd 5 + react-router 7 + TanStack Query 5；单包 `apps/frontend`；pnpm |
| 复刻 | 侧栏 / 顶栏 / 标签条 / 面包屑 / 内容区 / 移动端抽屉的**布局关系与视觉样式** |
| 不复刻 | Vben 的 monorepo、`@vben/*` 包、Vue 运行时、Pinia、preferences / access 模块、动态菜单、权限码、i18n、mock、示例页 |
| 不改 | `src/pages/**` 的业务字段、校验、口径、按钮语义；`api/**`、`providers/dataProvider|authProvider`、`types/**`、`utils/**` 的逻辑 |

改动面因此被限制在四类文件：外壳（`components/layout/**`）、主题（`theme.ts` / `index.css`）、
标签页状态（`providers/tabs.tsx`）、以及把外壳常量改成 token 的引用点。
**任何业务页面内的 JSX 结构不因本次改造而重排。**

### 1.1 视觉参考物与"复刻"的判定

参考物固定为 Vben Admin 5.7 的 **Ant Design Vue** 演示站（侧栏导航布局，亮 / 暗两套）。判定标准：

1. **结构与关系**：侧栏宽度与折叠宽度、顶栏高度、标签条是否住在顶栏内、内容区留白、折叠态 —— 一致；
2. **样式语言**：圆角档位、阴影层级、分隔线位置与深浅、字号与字重、选中态、悬停态、过渡时长 —— 一致；
3. **像素级不要求一致**。尺寸与色值以"实测标注"为准：落地前对着参考站截图逐项量一次，
   量到的值写进 `theme.ts` 的 token，**不写进组件**。

验收用截图对比（同页面、同窗口宽度、亮暗各一张），不做逐像素 diff。

## 二、布局规格（复刻范围）

### 2.1 结构与滚动责任

沿用"一屏高、窗口不滚"的骨架，滚动分区不变（这是已经验证过的部分，不因换外观而改）：

```
.shell                 100dvh，overflow: hidden —— 窗口永不滚
├── .shell-sider       品牌块（定高）/ 菜单区（自滚）/ 折叠开关（定高，钉在底部）
└── .shell-main
    ├── .shell-header  不在任何滚动容器里；左：面包屑，中：标签条（弹性），右：待办 / 头像
    └── .shell-content 只排版不滚
        └── [data-app-content] × N   每个标签页一份滚动容器
```

三条不得违反的约束：

- `100dvh` 不是笔误：移动端地址栏收起时 `100vh` 会把底部顶出视口；认不得 `dvh` 的浏览器保留上一行 `100vh`；
- **不要再对 `window` 做滚动**：`window.scrollY` 恒为 0，复位与记忆走 `utils/scroll.ts`；
- `HEADER_HEIGHT` 仍是单点：顶栏高度与侧栏品牌块由它下发，各写一个数会在两列之间露接缝。

### 2.2 需要复刻的元素（逐项）

| 区域 | 复刻项 | 备注 |
|---|---|---|
| 侧栏 | 宽度 / 折叠宽度两档；折叠后只留图标且居中；品牌块（标识 + 名称 + 副标题，折叠时只留标识） | 折叠按钮仍在侧栏底部，**不复刻** Vben 放在顶栏的写法 |
| 侧栏菜单 | 一级项圆角与内边距、选中态底色、悬停底色、图标与文字间距、分组标题（小字 / 次要色 / 缩进）、子菜单缩进与展开箭头、展开收起过渡 | 菜单数据仍来自 refine `useMenu` + `resources`，不新增菜单配置 |
| 顶栏 | 高度、左右内边距、底部分隔线、右侧操作区（待办徽标 + 头像菜单）、用户块（头像 + 昵称 + 下拉箭头） | 宽屏顶栏左侧只放面包屑；"收起侧栏"留在侧栏底部 |
| 标签条 | 胶囊形态、激活态、悬停淡入的关闭钮、固定标签的钉标、拖拽让位动画、右键菜单、溢出时可访问且滚动条不常显 | 标签条住在顶栏里，不单独占一条。**溢出用 antd 自带的「更多」下拉收口**，不做原生横滚：rc-tabs 用 transform 管理可视区间，加一层原生滚动会和它的溢出计算打架（记为 T-71 的偏差） |
| 面包屑 | 位置（顶栏左侧与内容区顶部二选一，定下来不再改）、层级、末级不可点 | 数据仍由 refine 的 `Breadcrumb` 提供，只改位置与样式 |
| 内容区 | 四周留白、容器圆角与描边、页面标题区与操作区的对齐 | 业务页内部不动结构，留白由外壳给 |
| 移动端 | < lg：侧栏变抽屉（比侧栏宽、含品牌块、点菜单项即关闭）；顶栏左侧出现"打开导航"；标签条横向滚动 | 与现状一致，只换样式 |
| 暗色 | 三级背景（底 / 容器 / 浮层）可区分、分隔线、次要文字、按钮与标签在暗底的可读性 | 12.5px 正文对比度仍要 ≥ 4.5:1 |
| 细节 | 圆角档位（小 / 中 / 大）、阴影层级、过渡时长与缓动、聚焦描边、滚动条（内容区与侧栏各一套） | 全部进 token，不散落在组件里 |

### 2.3 明确不复刻（防范围蔓延）

- Vben 的四种布局（侧栏 / 顶栏 / 混合 / 全内容）—— 只保留侧栏导航；
- 主题面板（可视化调色、圆角滑杆、灰阶模式）—— 保留现有三项低频开关：明暗、侧栏配色、密度；
- 水印、锁屏、国际化切换、全屏按钮、Vben 登录页的插画与动效；
- Vben 的 `preferences` 持久化结构与键名 —— 继续用 `gowork.ui-prefs`；
- Vben 的示例页、关于页、仪表盘 demo。

## 三、主题与样式规范

### 3.1 三层 token（唯一色彩来源）

| 层 | 位置 | 内容 | 谁读它 |
|---|---|---|---|
| 品牌层 | `theme.ts` 的 `brand` 色阶 | 主色及其中间档、语义色五档（success / processing / warning / error / neutral） | 下面两层都从这里取 |
| 组件层 | `theme.ts` 的 `buildThemeConfig()` | antd 的 `token` 与 `components` 覆写（圆角、控件高度、间距、字号） | antd 组件 |
| 结构层 | `index.css` 的 CSS 变量（`--shell-*` / `--sider-*` / `--gap-*`） | 外壳尺寸、侧栏配色、间距标尺 | 外壳与 `index.css` 自身的结构样式 |

规则（沿用现有，改造中不得放宽）：

- 组件里**不写死颜色**；新增色先加进 `brand`。
- 侧栏子树的结构样式只引用 `--sider-*`，**不引用** `--ant-*`：侧栏切深色时页面主题不跟着变，深底上会留白线。
- 侧栏仍是独立的 `ConfigProvider` 且 `cssVar: false`：否则两块主题撞在同一批类名上，切侧栏会连内容区一起变。
- 密度只走 `--gap-*` / `--pad-block` 一套标尺，不新增 `[data-density='compact']` 覆写。

### 3.2 取值来源与可读性优先

- 尺寸（侧栏宽 / 折叠宽、顶栏高、圆角、间距、字号、行高）与颜色以参考站实测为准，
  在 `theme.ts` 顶部集中声明并注明来源。演示站取不到登录后页面时（2026-11-09：先对无头浏览器
  全部返回 503，晚些能打开首页 5.8.0 但登录不可用），以 5.8 源码 `@vben/preferences` 的
  `defaultPreferences` 为基线，
  同样注明；实测值与源码值不一致时以实测为准，并把偏差写进 T-71 的偏差清单。
- **任何取值若使 12.5px 正文对比度低于 4.5:1，以可读性为准** —— 不接受为了像而看不清。
- `HEADER_HEIGHT` / `SIDER_WIDTH` / `SIDER_COLLAPSED_WIDTH` / `MOBILE_SIDER_WIDTH` 四个常量换值后，
  必须在 375 / 768 / 1024 / 1440 四档各走查一次（品牌块与顶栏底边必须齐平）。

## 四、多标签页行为定义（含 keepAlive 边界）

### 4.1 标识与地址

| 规则 | 定义 |
|---|---|
| 标签 key | **`pathname`**（不是完整路径）：`/products?page=2` 与 `?page=3` 是同一页翻页，算一个标签 |
| 标签 URL | 记住完整地址（含 query / hash），切回时导航到该地址 |
| 多实例 | `/products/show/1` 与 `/show/2` 是两个标签、两份实例，各自读到自己的 `:id` |
| 未登记路径 | 外壳预检（`isKnownPath`），未知路径直接回首页，**不留死标签** |

### 4.2 行为清单

| 行为 | 定义 |
|---|---|
| 打开 | 菜单 / 链接 / 手输地址进入 → 追加到末尾并激活；已存在则只激活并更新 URL |
| 激活 | 点标签 → 导航到该标签 URL（单向驱动：地址栏是唯一真相） |
| 关闭 | 关当前页 → 落右邻，无右邻落左邻，都没有回首页；关非当前页 → 视图不动 |
| 固定 | 首页固定：不可关闭、始终第一位 |
| 拖拽 | 按住拖动调整顺序；拖动时其余标签让位；**拖动不导航**；顺序不落盘 |
| 右键菜单 | 刷新（重挂载该页）、关闭、关闭其他、关闭左侧、关闭右侧、全部关闭（固定标签保留） |
| 上限 | 最多 **10** 个标签（固定标签不计入）；超出时自动关闭**最久未激活**的非固定标签，并用顶部 message 提示一句（不弹窗） |
| 未保存提醒 | 切到**已打开**的标签页不拦；其余离开（关标签、点菜单跳走、刷新 / 关浏览器）沿用现有 `UnsavedTabGuard` 的确认语义 |
| 顶部进度条 | 保留，仍只认 `api/client.ts` 的并发计数 |
| 持久化 | 标签列表与顺序**不落盘**，刷新后按打开顺序重来 |

### 4.3 keepAlive 缓存边界（本次接受的简化）

这是本方案与现状**唯一的体验差异**，必须写清"哪些一定还在、哪些允许丢"。

**缓存单位**：一个标签页（key = pathname）对应一份页面实例；是否缓存由该路由的 `keepAlive` 标记决定。

| 页面类型 | keepAlive 默认 | 理由 |
|---|---|---|
| 列表页 | 是 | 筛选、排序、已加载分页、滚动位置都在原组件里 |
| 详情页 | 是 | 只读、状态轻；面板展开状态需要保留 |
| 新建 / 编辑页 | 是 | 半填的表单是最不能丢的东西 |
| 报表 / 看板 / 待办 | 是 | 筛选与维度切换状态 |
| 系统页（账号 / 操作日志） | 否 | 没有"填一半再回来"的场景，表却最重；切回重新取数 |
| 登录 / 403 / 404 / 外链 | 否 | 无状态 |

**切回时必须还在**（硬要求，逐条验收）：

1. 列表的筛选条件、排序、已加载的批次与无限滚动的累计结果；
2. 滚动位置（按标签 key 记忆；`display:none` 会丢 `scrollTop`，切回时按记忆值恢复）；
3. 表单里已经输入但未提交的内容；
4. 展开 / 折叠、页签、`Segmented` 视图等控件状态；
5. 弹窗 / 抽屉的开关状态（打开着切走再切回仍打开）。

**允许丢失**（简化后的代价，写进文档就不算 bug）：

1. 超出 10 个标签上限、被 LRU 淘汰的页面状态 —— 切回即重新挂载、重新请求；
2. 浏览器前进 / 后退导致的页面内状态差异（不承诺还原到某一帧）；
3. 刷新页面后的标签列表、滚动位置、表单内容（**不持久化到 sessionStorage / localStorage**）；
4. 同一页面同时存在多份实例（详情页按 pathname 天然分开，除此之外不支持"同一列表开两个筛选状态"）；
5. 未标记 `keepAlive` 的页面每次进入都是新的。

**实现约束**（给实现者，不是给验收者）：

- 缓存的是**组件实例**，不是 DOM 快照：不做 DOM 搬运；若评估第三方 keep-alive 库
  （如 `react-activation`），必须先论证它不破坏 `useRoutes` + `UNSAFE_LocationContext` 的多实例匹配；
- 每个缓存实例必须**独立匹配路由、独立读 location**（现状 `tab-panes.tsx` 的做法），
  否则两个详情页会读到同一个 `:id`；
- 无限滚动的 `IntersectionObserver` root 必须取 `node.closest('[data-app-content]')`，不能全局查，
  否则切回来会绑在别人的 pane 上；
- 淘汰实例时同时丢弃其 query 缓存引用，避免内存里留下没人用的数据。

### 4.4 状态机

地址栏是唯一真相：`location` 变化 → 打开 / 激活标签；点标签 → `navigate` → 再由上一条激活。
不允许标签自己维护"当前页"——两份真相的 bug 在这一类实现里占多数。

## 五、不保留 Vben 结构的约束条件

以下为**硬约束**，违反任何一条都算超出本次需求：

1. **不引入 Vue 生态**：`vue`、`@vben/*`、`pinia`、`vue-router`、`element-plus`、`naive-ui`、
   `ant-design-vue` 一律不进 `package.json`。
2. **不 monorepo 化**：仍是 `apps/frontend` 单包；不引入 `turbo`、`packages/@core`、`internal/*` 配置包；
   不改根 `pnpm-workspace.yaml` 的用途。
3. **不迁 Vben 目录规范**：不采用 `#/` 别名、`views/`、`router/routes/modules`；
   继续 `@/*` → `src/*`、`pages/` + `config/resources.tsx`。
4. **不引入 Vben 的权限体系**：不做 `accessMode`、不做动态菜单、不做权限码（`accessCodes`）。
   权限仍是"菜单全可见 + 后端 403 兜底 + 前端仅 `role === 'admin'` 一处"。
5. **不替换框架层**：refine 的 `resources` / `useTable` / `useForm` / `useShow` 与
   `dataProvider` / `authProvider` 不动。
6. **不复刻 Vben 的内部 API**：不实现 `useVbenForm`、`useVbenVxeTable`、`preferences` store 之类的等价物。
7. **不引入 Tailwind / shadcn**：样式继续走 antd token + `index.css` 的结构变量；
   不新增 CSS-in-JS 或原子类体系。
8. **不改后端**：本次不需要任何接口或字段变化，外壳是纯前端改造。
9. **不改业务页面内部结构**：`src/pages/**` 只允许两类改动 —— 把外壳常量 / 颜色的引用换成 token、
   增加（可选）`meta.keepAlive` 声明；不允许重排表单、表格、面板结构。
10. **不做行为回退**：现有五条硬约束继续成立 —— 窗口不滚、`HEADER_HEIGHT` 单点、`100dvh`、
    未保存提醒只拦真离开、不使用 `useBlocker`（本项目是 `<BrowserRouter>`，不是 data router）。

## 九、落地结果与偏差（2026-11-09）

按 T-65～T-70 落地后，与上面规范不一致的地方只有下面五条，逐条记原因和主张：

1. **视觉基线来自源码默认值，不是截图实测。** 2026-11-09 首次访问时演示站把 `/js/*` 全部
   返回 503；稍后再访问，首页能打开（版本已是 5.8.0），但登录过不去——协议勾选点不动、
   点「登录」不离页，疑似其 mock 接口对外不可用，因此始终拿不到登录后的侧栏与标签条。
   改用仓库 `@vben/preferences` 的 `defaultPreferences`（`sidebar.width` 224、
   `collapseWidth` 60、`header.height` 50），出处写在 `theme.ts`。
   页面上量到差异时改 `shell` 一处，不回填 CSS。
2. **标签溢出不横滚，用 antd 自带的「更多」下拉。** rc-tabs 用 transform 管理可视区间，
   外面再加一层 `overflow-x` 会和它的溢出计算打架（表现为最后几个标签点不到）。
3. **系统两页不参与缓存。** 账号与操作日志标了 `keepAlive: false`：没有「填一半再回来」
   的场景，表却最重。4.3 的表已补这一行。
4. **主色没换。** 仍是现有 `brand` 色阶，不采用 Vben 的 `hsl(212 100% 45%)` ——
   现有 `primarySoft`、边框色与暗色可读性都是从这组值推出来的，换主色要整组重算对比度，
   而"像不像"的收益不足以抵这次重算的风险。
5. **收起宽度 60 牵动了两处 antd 行为。** 内联折叠菜单的宽度是 `controlHeightLG * 2`
   （≈80）而不是 `Sider` 的 `collapsedWidth`，所以两份 `Menu` token 都要显式写；
   折叠态还必须去掉 `scrollbar-gutter`，否则 60 的侧栏里菜单只剩 50，图标贴边。

## 十、与 Vben 源码的逐项比对（2026-11-09）

演示站登录不可用（见第九节第 1 条），所以这一轮比对读的是源码：
`@core/ui-kit/menu-ui/src/components/menu.vue`、`@core/ui-kit/tabs-ui/src/components/tabs-chrome/tabs.vue`。
凡是"未改"的，都记了不照抄的理由——照抄一项就要连带改一处结构。

| 项 | Vben 源码 | 本项目（调整后） | 结论 |
|---|---|---|---|
| 菜单项高度 | `--menu-item-height: 38px` | 38px | 一致，未动 |
| 菜单项圆角 | `is-rounded` 时 8px | 8px（原 6） | **已对齐** |
| 菜单项左右外边距 | `--menu-item-margin-x: 8px` | 8px | 一致 |
| 菜单项上下外边距 | `--menu-item-margin-y: 2px` | 2px（原为 antd 默认 4） | **已对齐** |
| 菜单项字号 | `--menu-font-size`（14） | 14（antd 默认） | 一致 |
| 菜单选中底色 | 浅色 `hsl(primary / 15%)` | `primarySoft` #eff4ff（≈9%） | 未改：它是全站统一的"浅底"（表格 hover、focus ring 同色），单独加深会让一页里出现两种选中色 |
| 菜单折叠态内距 | `23.5px / 0`，图标居中 | antd 折叠布局 + `collapsedWidth: 60` | 未改：antd 的折叠项自带居中，照抄内距会溢出 60 的侧栏 |
| 标签形状 | 仅上圆角 7px（chrome 风格） | 四角 7px 胶囊 | 未改：chrome 依赖标签贴住内容区顶边，本项目标签住在顶栏里（§2.2），贴边会与顶栏底边框抢同一条线 |
| 标签字号 | `text-sm` = 14px | 14px（原 13） | **已对齐** |
| 标签左右内距 | 主体 8 / 16，另有 6px 外壳内距 | 12 / 12 | 近似：本项目标签不带图标，对称内距更稳 |
| 标签间距 | `--gap: 7px` 再叠加 `-mr-3`（视觉约 2px） | 6px | 近似：照抄 7 会明显更挤 |
| 标签上下内距 | 0（贴顶） | 5px | 未改：胶囊需要上下留白才立得起来 |
| 关闭钮 | 12px，悬停圆底 | antd 默认 12px | 一致 |
| 固定标签标记 | `Pin` 14px | `PushpinOutlined` 11px | 近似：顶栏里的标签更小，14px 会盖住文字 |
| 面包屑位置 | 顶栏左侧 | 内容区顶部（refine 的 `PageHeader`） | 未改：走的是 §2.2 给的第二个选项 |

实测（dev + 真后端，1440）：菜单项 `height 38 / radius 8 / margin 2px 8px`；
标签 `radius 7 / padding 5px 12px / font 14 / 高 35`，激活底色 `#eff4ff`。
